{%- comment -%} THE /updates/ FEED CARD'S EVIDENCE LINE (GROWTH-3 review 1, D1). The card used to print the record's stored update_consensus_summary as is, and that field opened "WAIT: OBS Studio 32.2.2 has 53 user reports found." -- a verdict without the setup it applies to, sitting beside a count, so it read as "53 reports, so wait". The writer now stores lib/patch_decision.summary_line: the verdict AND its scope first, then the exact patch, then the page's own recommendation line ("WAIT if you use macOS 27.2: OBS Studio 32.2.2. A user reports, and OBS confirms, ..."). The card prints that stored line only while it opens with exactly the verdict and scope this page renders (the same gate every other surface renders) AND ends with exactly this page's line. A stored line that lags the policy -- it catches up at the product's next promotion -- is not printed: the card then shows the gate's verdict, scope and line, so the feed can never show a verdict, or a reason, that the page does not. Only the patch name between them is the stored text. Review 2 (LOW-4). The line is the FEED's form of the page's line (lib/patch_decision.feed_body): a card lists no reports, so "...; they are listed below." and its two siblings end at the clause before (the same three replacements, in the same order). The fallback line names the exact patch as the stored one does (product, version and, for the two build-aware products, the build -- lib/patch_identity.patch_display_label); it used to drop it. AN OFFICIAL VERDICT PRINTS AT ANY REPORT COUNT (AUX-097). The line used to need a stored summary, and only a writer stores one -- on a page with reports. So the 17 zero-report SECURITY UPDATE cards and the zero-report AVOID card for the withdrawn KB5079391 printed no verdict at all, beside an "Insufficient data" evidence pill, while their pages stated the official verdict. An AVOID or SECURITY UPDATE the gate prints now always gives the card its line, composed exactly like the fallback below (verdict and scope, the exact patch, the page's line in feed form). A zero-report page with no verdict (INSUFFICIENT DATA) still has no line. lib/verdict_projection.feed_line states this contract in Python for QA, and test_growth3_verdict_policy renders this file against it over every page. Input: include.item the feed item (a site.pages patch record) include.summary the card's stored evidence summary, already cleaned; '' when none Output: feed_summary_line the line to print, or '' (no evidence block) A record with no stored summary keeps no evidence block unless its verdict is official. One with a summary but no gate line (a non-official page with no reports) keeps its stored text.
