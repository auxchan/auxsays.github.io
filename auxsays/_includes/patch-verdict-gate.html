{%- comment -%} THE VERDICT GATE (GROWTH-3). Every surface that prints a verdict renders this file (patch-decision.html for the patch page and the homepage, patch-table-row.html for product and vendor tables, patch-feed-summary.html for the /updates/ feed, updates/my-stack.md), so they cannot disagree, and a stale or hand-written stored label can never publish a verdict. IT DECIDES NO VERDICT. Every verdict is decided by lib/patch_decision.decide in Python and written per page to _data/verdict_projection.yml by build_verdict_projection.py at deploy, BEFORE QA and BEFORE Jekyll: AVOID (the lifecycle record), SECURITY UPDATE (Microsoft's stored release type, with its warning panel when a supported reason adds one), WAIT and TEST FIRST (a supported reason entry). This file looks up the row for its page's exact identity (product_id|update_version|target_build) and prints the verdict, scope, line, panel and recommendations in it, as they are. It re-derives nothing. Round 0 re-implemented the support rule here with a URL-only check and published verdicts the authority refused (review 1, D2). Until review 2 it still derived the two official verdicts itself, matching the lifecycle file and parsing "YYYY-MM B" with slice and plus: 0, and QA could not see where that parted from Python (LOW-1): lifecycle builds written as YAML numbers made Python say AVOID while both pages printed INSUFFICIENT DATA, and "2026-3x B", "2026-+3 B" and "2026-1 B" read as security updates here only. No row, or no projection at all (a local render, a fresh checkout): INSUFFICIENT DATA, no panel -- fail closed. A row is printed only when it is well formed, exactly as lib/verdict_projection.printed_row states it for QA: a published verdict, a non-empty line, and a scope where the verdict carries one (AVOID, WAIT, TEST FIRST) and none on SECURITY UPDATE. Input: include.record a patch page (page) or a site.pages item include.count that record's report count, as a number Outputs: gate_label the published verdict gate_scope "if ..." / "when ..." qualifier for WAIT / TEST FIRST, "for new installations" for AVOID (it applies to installing it), else ''. Every surface prints it beside gate_label (review 1, D1) gate_body the recommendation line; '' only for a zero-report page with no verdict, whose existing line stays gate_official true for AVOID and SECURITY UPDATE (facts, not report evidence) gate_panel_heading, gate_panel_text the security page's warning box, else '' gate_recommendations the Recommendations list an official verdict carries (AVOID), else an empty list The INSUFFICIENT DATA lines below are lib/patch_decision.public_body's, character for character; test_growth3_verdict_policy renders this file against Python over every page.
