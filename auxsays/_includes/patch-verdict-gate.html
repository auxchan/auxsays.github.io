{%- comment -%} THE VERDICT GATE (GROWTH-3). The render-time mirror of lib/patch_decision.decide: it applies the owner's verdict policy to the record's stored FACTS, and the stored verdict label plays no part. Every surface that prints a verdict renders this file (patch-decision.html for the patch page and the homepage, patch-table-row.html for product and vendor tables, updates/my-stack.md), so they cannot disagree, and a stale or hand-written label can never publish a verdict the policy does not support. Precedence, first match wins, exactly as decide(): R1 AVOID an official withdrawal for new installations in _data/patch_lifecycle.yml for this exact KB and OS build (one verified exception today) R2 SECURITY UPDATE Microsoft's stored release-health type "YYYY-MM B" on a Windows record; reports never override it, a supported reason only adds a warning panel R3/R4 WAIT / TEST FIRST a reviewed entry in _data/verdict_reasons.yml for this exact page whose cited rows are ALL still among the page's counted sources (accepted_report_sources). A withdrawn row drops the entry: fail closed R5/R6 INSUFFICIENT DATA Report count, sentiment, theme, severity, maturity and dates are not read here. Input: include.record a patch page (page) or a site.pages item include.count that record's report count, as a number Outputs: gate_label the published verdict gate_scope "if ..." / "when ..." qualifier for WAIT / TEST FIRST, "for new installations" for AVOID (it applies to installing it), else '' gate_body the recommendation line; '' only for a non-official zero-report page, whose existing line stays gate_official true for AVOID and SECURITY UPDATE (facts, not report evidence) gate_panel_heading, gate_panel_text the security page's warning box, else '' The wording is lib/patch_decision.public_body's, character for character; test_growth3_verdict_policy compares the two over every page.
