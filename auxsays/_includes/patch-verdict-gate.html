{%- comment -%} THE VERDICT GATE (GROWTH-3). Every surface that prints a verdict renders this file (patch-decision.html for the patch page and the homepage, patch-table-row.html for product and vendor tables, patch-feed-summary.html for the /updates/ feed, updates/my-stack.md), so they cannot disagree, and a stale or hand-written stored label can never publish a verdict. IT DECIDES NO REASONED VERDICT. WAIT, TEST FIRST and a security page's warning panel are decided by lib/patch_decision.decide in Python, from the counted evidence and the reviewed reason entries, and written per page to _data/verdict_projection.yml by build_verdict_projection.py at deploy, BEFORE QA and BEFORE Jekyll. This file looks up the row for its page's exact identity (product_id|update_version|target_build) and prints the verdict, scope, line and panel in it, as they are. It never reads a reason entry or a cited report: round 0 did, with a URL-only copy of the support rule, and published verdicts the authority refused (review 1, D2). No row, or no projection at all (a local render, a fresh checkout): no WAIT, no TEST FIRST, no panel. Precedence, first match wins, exactly as decide(): R1 AVOID an official withdrawal for new installations in _data/patch_lifecycle.yml for this exact KB and OS build (one verified exception today): a stored fact R2 SECURITY UPDATE Microsoft's stored release-health type "YYYY-MM B" on a Windows record: a stored fact. Reports never override it; a projected SECURITY UPDATE row only adds its warning panel and line R3/R4 WAIT / TEST FIRST the page's projected row, when it says WAIT or TEST FIRST with a scope R5/R6 INSUFFICIENT DATA Report count, sentiment, theme, severity, maturity and dates are not read here. Input: include.record a patch page (page) or a site.pages item include.count that record's report count, as a number Outputs: gate_label the published verdict gate_scope "if ..." / "when ..." qualifier for WAIT / TEST FIRST, "for new installations" for AVOID (it applies to installing it), else ''. Every surface prints it beside gate_label (review 1, D1) gate_body the recommendation line; '' only for a non-official zero-report page, whose existing line stays gate_official true for AVOID and SECURITY UPDATE (facts, not report evidence) gate_panel_heading, gate_panel_text the security page's warning box, else '' The official lines are lib/patch_decision.public_body's, character for character; test_growth3_verdict_policy renders this file against Python over every page.
