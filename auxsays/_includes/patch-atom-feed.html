{%- comment -%} THE PATCH VERDICT FEEDS (P8): one Atom feed per product tracker and one for every product. WHAT AN ENTRY IS. A patch page and the verdict that page prints today. AUXSAYS stores no history of verdict changes: a record's status_events hold its publication and its report-count updates, never a verdict, and the verdict itself is decided at deploy (lib/patch_decision.decide, projected to _data/verdict_projection.yml). So a feed lists the NEWEST patch pages, by their stored release date, each with its current verdict, and its subtitle says so. It never calls an entry a change. NO SECOND VERDICT AUTHORITY. The verdict, its scope and its line come from patch-verdict-gate.html, the file every other surface prints a verdict from, so a feed cannot say what the page does not. INSUFFICIENT DATA is written "no verdict yet", as the page's search title writes it. DATES. An entry's is the record's record_last_updated (the moment a writer last changed it), else its release date: the same stored dates, under the same three tests, as sitemap.xml (written as a date, readable, between 2000 and this build). A record with neither is skipped, never dated with the build time. The feed's own is its newest entry's; only a feed with no entry carries the build time, because Atom requires the element and nothing else is true of it. Input: include.product_id a product id, or empty for every product include.limit the most entries to list include.title_name the name the feed title and subtitle use include.alternate the page the feed belongs to (a product tracker, or the Patch Feed) page.url the feed's own URL Plain Liquid apart from where / sort / absolute_url / xml_escape, so the test can render this very file with the Liquid gem (scripts/tests/test_patch_atom_feeds.py).
