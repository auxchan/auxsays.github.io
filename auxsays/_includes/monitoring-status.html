{%- comment -%} Shared per-patch MONITORING STATUS field. SINGLE SOURCE OF TRUTH for the monitoring axis on every surface (product/vendor history rows, the patch feed, and the patch-detail page). This is an evidence/collection status, NOT a verdict, and it is kept separate from the AUXSAYS verdict. Derived ONLY from structured per-exact-patch telemetry in _data/evidence_method_health.yml (EMH), joined on the CANONICAL PATCH IDENTITY (product_id, update_version, target_build). The build component matters: a build-aware product can ship several builds under one version, and every one of their EMH rows carries the same update_version. Joining on the version alone let a build with NO telemetry of its own inherit a sibling's -- the ladder's rule 1 would see rows and report a monitoring state that build never earned, which is a fail-OPEN in the one place that must fail closed. An empty build on both sides is a no-op, so version-only products are unaffected. No manual allowlist -- "monitored" means EMH rows exist FOR THIS EXACT PATCH. It FAILS CLOSED: missing, stale, future, disabled, blocked, broken, partial, low-confidence, or manual-review telemetry can never produce a clean "no reports" read. Inputs: include.product_id -- exact tracked product id include.version -- exact patch version (numeric YAML versions are string-normalized) include.target_build -- exact vendor build for build-aware products ('' when not build-aware) include.published_at -- record release timestamp (ISO); gates post-release runs include.report_count -- accepted patch-specific community report count include.mode -- 'full' (detail card) | 'cell' (table cell) | 'feed' (feed line) Fail-closed ladder (first match wins): 1 no matching rows -> OFFICIAL SOURCE ONLY 2 every matching row disabled -> OFFICIAL SOURCE ONLY 3 no valid, non-future timestamp among usable rows -> COLLECTION STALE 4 valid usable timestamps exist, but none are post-release -> NOT YET MONITORED 5 no fresh post-release usable methods -> COLLECTION STALE 6 zero healthy methods and a blocked/broken method present -> COLLECTION BLOCKED 7 any degraded telemetry (bad status / partial-disabled / invalid|future ts) -> MONITORING DEGRADED 8 healthy methods below minimum -> INSUFFICIENT COVERAGE 9 accepted reports > 0 -> MONITORING ACTIVE 10 otherwise -> NO ACCEPTED PATCH-SPECIFIC REPORTS A healthy completed method is: usable (not disabled) AND fresh (0 <= age <= monitoring_max_age_days) AND post-release (last_run >= published_at) AND status success or no_results (the validator gives no_results no failure semantics).
