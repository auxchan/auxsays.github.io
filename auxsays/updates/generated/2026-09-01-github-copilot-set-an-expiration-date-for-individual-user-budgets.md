release_summary: "You can now set an optional expiration date on an individual user budget, and GitHub removes the budget\
  \ on that date. This capability is generally available. The user then falls back to the next budget that applies to them\
  \ (i.e., their cost center per-user budget or otherwise your universal budget).\n\n\n Previously, you had to remove every\
  \ temporary budget override by hand, creating recurring cleanup work at enterprise scale.\n\n\n When you create or edit\
  \ an individual user budget, you can choose:\n\n\n\n No expiration, which is the default and matches current behavior.\n\
  \ Expiration at the start of the next billing cycle.\n Expiration on a specific date.\n\n\n\n\n You can change or clear\
  \ an expiration date at any time.\n\n\n Set an expiration date in your billing settings, or use the expires_at field in\
  \ the Budgets REST API when you create or update a budget.\n\n\n Expiration dates are available for the GitHub Copilot Business\
  \ and Copilot Enterprise plans.\n\n\n Learn more about setting up budgets and the Budgets REST API .\n\n\n\n The post Set\
