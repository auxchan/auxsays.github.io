release_summary: "GitHub Copilot Fusion is generally available. Instead of picking a model for each task, choose Copilot Fusion\
  \ and let Copilot intelligently route and orchestrate which models it uses for you.\n\n\n Copilot Fusion brings together\
  \ Project HydraFusion’s multi-model orchestration and Copilot auto model selection’s fine-tuned model selection, leveraging\
  \ the benefits of both to balance performance and cost efficiency.\n\n\n Since Project HydraFusion launched, we’ve improved\
  \ its performance. In the Artificial Analysis Coding Agent Index, Copilot Fusion Max scored 60, within two points of Claude\
  \ Code with Opus 5.5 Max. It delivered that result at about half the average API cost per task, using about half as many\
  \ tokens and taking about 40% less time per task.\n\n\n Smarter choices for developers\n When you select Copilot Fusion\
  \ in the model picker, you aren’t selecting a specific model. You’re choosing a system that routes and orchestrates models\
  \ for each task. There’s no need to switch models during a task or decide which model suits each step. For each prompt,\
  \ Copilot Fusion determines which models to use and how they work together, while you choose the right level of effort.\n\
  \n\n To use it, select Copilot Fusion in the model picker, then choose the effort level.\n\n\n\n Fusion Standard: Prioritizes\
  \ versatile models for everyday coding.\n Fusion High: Prioritizes capable models for challenging tasks and deeper reasoning.\n\
  \ Fusion Max: Prioritizes the most capable models for the most demanding tasks and complex reasoning.\n\n Watch as Copilot\
  \ Fusion analyzes each task and selects a model to complete it, orchestrating multiple models through the following workflows\
  \ when needed.\n\n\n\n Single: One model solves the task directly.\n Cascade: An efficient model drafts a response. A quality\
  \ check determines whether to accept it or escalate to a stronger model.\n Critique: One model drafts an initial response,\
  \ another model reviews it, and the original model revises.\n\n\n\n\n More control for administrators\n Administrators control\
  \ which models Copilot Fusion can use and whether Copilot Fusion is the default.\n\n\n\n Copilot Fusion only uses the models\
  \ that are enabled in your enterprise and organization model policies . Enterprise administrators can view what models Copilot\
  \ Fusion picks from, independently set each model’s effective policy state, and disable models for Copilot Fusion without\
  \ disabling the model for everyone. See Manage availability of default models .\n Administrators can set Copilot Fusion,\
  \ at any effort level, as the default model for Copilot users with Enterprise managed settings. To configure settings, see\
  \ Enterprise managed settings .\n\n “GitHub Copilot Fusion Standard has improved token efficiency across AT&T by automatically\
  \ selecting the right model for the task, reducing unnecessary spend and preserving capacity for higher-value work. Previously,\
  \ developers would often choose a more powerful model for a complex task and forget to switch back for everyday activities.\
  \ Copilot Fusion eliminates that friction, optimizing model selection without requiring developers to manage it themselves.\
  \ We’ve also seen its decision-making improve over time, giving developers greater confidence to focus on their work while\
  \ Copilot handles model selection.”\n\n Hari Pokhrel, Principal Software Engineer, AT&T\n\n\n Billing\n When you use Copilot\
  \ Fusion you’re billed for each model it uses, at each model’s standard rate. For a limited time, users on paid Copilot\
  \ plans will receive a 30% discount on model costs when using Copilot Fusion.\n\n\n Get started\n Copilot Fusion is available\
  \ on all Copilot plans in Visual Studio Code, the GitHub Copilot app, GitHub Copilot CLI, and JetBrains IDEs. Support for\
  \ additional clients is coming soon.\n\n\n Update your client to try it out. Open the model picker, select Copilot Fusion\
  \ , and choose an effort level.\n\n\n\n Note for research preview participants: if you previously enabled auto, HydraFusion,\
  \ or HydraFusion Max, your selections will automatically transition to the corresponding Copilot Fusion effort levels.\n\
  \n\n\n To learn more, see our documentation on GitHub Copilot Fusion and share your feedback in the GitHub Community .\n\
  \n\n\n The post Route and orchestrate models with GitHub Copilot Fusion appeared first on The GitHub Blog ."
