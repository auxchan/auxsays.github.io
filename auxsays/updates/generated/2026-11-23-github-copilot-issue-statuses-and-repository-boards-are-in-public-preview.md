release_summary: "Open or closed doesn’t always tell you where an issue stands. You can now use more specific statuses to\
  \ give your team and agents shared context about what’s in flight and what to work on next, then visualize your progress\
  \ with repository boards.\n\n\n Issue statuses\n Track progress directly on an issue. Choose a status when creating an issue\
  \ or change it from the issue header. You’ll see it reflected in issue icons across the repository issues page, the issues\
  \ dashboard , and repository boards, where you can use the status: filter to find the issues you’re looking for.\n\n\n Available\
  \ statuses are:\n\n\n\n Backlog\n Todo\n In progress\n In review\n Done\n Not planned\n Duplicate\n\n Automated status updates.\
  \ To help keep your statuses accurate, the following automations are applied to your issues:\n\n\n\n Linking a draft pull\
  \ request to an issue moves the issue to In progress .\n Marking a draft pull request as Ready for review moves the issue\
  \ to In review .\n Linking an open pull request to an issue moves the issue to In review .\n Assigning a user to an issue\
  \ moves it to Todo .\n Assigning an agent to an issue moves it to In progress .\n If a GitHub Project has a status value\
  \ that matches an issue status, changing either status updates the other.\n\n GraphQL, REST API, and MCP server support.\
  \ Automations and agents can read an issue’s status, set a status, and choose an initial status when creating an issue.\
  \ Status changes are also available as an automation trigger for Copilot automations.\n\n\n Repository boards\n Repository\
  \ saved views now support a board layout, providing a quick way to see how work is progressing and update issues without\
  \ leaving the repository. When you need more advanced planning features for your workflows, you can use a GitHub Project\
  \ .\n\n\n\n Create a new view or open an existing view and switch to the board layout using the View options ⚙️ menu.\n\
  \ Group by status to see your issues organized, and drag an issue to another column to update its status.\n Configure columns,\
  \ swimlanes, visible fields, and sorting to customize your board.\n\n\n\n\n\n\n Issue fields are now independent of issue\
  \ types\n Previously, issue fields other than Priority required mapping to an issue type to be shown on an issue. With this\
  \ change, you can now add any issue field to an issue regardless of the type through the cog ⚙️ menu in the fields section\
  \ of the issue sidebar. Fields will continue to only show by default if they have been pinned to a type. Learn more about\
  \ issue fields in the documentation .\n\n\n Join the community discussion .\n\n\n\n The post Issue statuses and repository\
  \ boards are in public preview appeared first on The GitHub Blog ."
