release_summary: "GitHub Copilot code review now helps you catch more issues earlier, with less effort. Adaptive matches review\
  \ depth to each pull request, so routine changes get a quick pass and risky changes get a deeper look. Reviews can also\
  \ draw on related repositories and flag exposed secrets before they reach your main branch. Features in public preview are\
  \ subject to change.\n\n\n Adaptive, cross-repository context, and secret detection are available to Copilot Pro, Pro+,\
  \ Max, Business, and Enterprise plans.\n\n\n \U0001F3AF Adaptive: The right review effort for each pull request\n Today,\
  \ someone has to decide in settings or when requesting a review, what review effort level each pull request needs. A documentation\
  \ update may only need Lite , while a change to authentication logic benefits from Max . Adaptive makes that choice for\
  \ you. Copilot looks at each pull request’s complexity and risk, then reviews it with Lite , Balanced , or Max . Each review\
  \ shows which effort level Adaptive picked. Adaptive is now in public preview.\n\n\n\n\n\n ⚙️ Configure Adaptive\n You can\
  \ select Adaptive for a single pull request from the “Reviewers” bar, or set it as your default review effort in personal,\
  \ repository, organization, or enterprise settings. Balanced remains the default review effort level.\n\n\n\n\n\n Adaptive\
  \ never picks a level above the maximum review effort level set for your enterprise, organization, or repository. To learn\
  \ more, see Configuring code review by GitHub Copilot .\n\n\n ⚠️ The maximum review effort level configured in Copilot code\
  \ review settings determines which levels Adaptive can choose from.\n\n\n \U0001F517 Cross-repository context\n Changes\
  \ often affect code outside the repository you’re working in. With cross-repository context, Copilot code review can read\
  \ related public repositories during a review, so it can find code in other repositories that depends on your change. It\
  \ can also find relevant context from documentation stored in other repositories, custom instructions and skills, and more.\n\
  \n\n\n\n\n Cross-repository context is now in public preview for public repositories.\n\n\n \U0001F510 Secret detection\
  \ in reviews\n Copilot code review can now flag exposed secrets in your pull requests. Using both deterministic and non-deterministic\
  \ approaches, Copilot code review points out exposed credentials in review comments, so you can remove them before you merge.\
  \ Secret detection in Copilot code review is now in public preview.\n\n\n Secret detection is supported for the following\
  \ types:\n\n\n\n Known formats. GitHub collaborates with 150+ technical partners through GitHub’s secret scanning partnership\
  \ program in order to build out high-confidence secret detectors. These 500+ secret types use deterministic methods like\
  \ regex to find secrets.\n AI/ML-detected secrets. Copilot code review also detects secrets without recognizable format.\
  \ It uses LLMs and GitHub’s purpose-built model for secret to find exposed secrets.\n\n\n\n\n To turn on secret detection,\
  \ go to your repository or organization settings and select Copilot , then Code review . To learn more, see Secret scanning\
  \ .\n\n\n \U0001F4CA Track review outcomes by repository\n You can now see how Copilot code review feedback is addressed\
  \ and utilized in each repository. To get started, navigate to the Insights tab of any repository you have read access to,\
  \ then click Repository insights . For details, see Track Copilot code review outcomes by repository with Repo Insights\
  \ .\n\n\n ☁️ Copilot code review for Azure DevOps\n Copilot code review for Azure Repos, previously in public preview, is\
  \ now generally available. Teams that host code in Azure DevOps can get Copilot reviews on their pull requests, with comments\
  \ and suggested changes on the lines that need attention.\n\n\n\n Flexible setup: Administrators turn on Copilot code review\
  \ at the organization, project, and repository level. Add a branch policy to request a Copilot review automatically on pull\
  \ requests that target a branch, or request one manually from the Reviewers list.\n Review effort levels: Set a default\
  \ of Lite or Balanced for a project or repository, or choose a different effort level for a single review.\n Custom instructions\
  \ and skills: Tailor Copilot’s feedback to your team’s standards with custom instructions and agent skills.\n Faster follow-up:\
  \ Apply and commit Copilot’s suggestions and resolve the related comments at the same time.\n Admin visibility: Audit log\
  \ events record when Copilot code review is turned on or off and when its settings change.\n Azure billing: Usage is billed\
  \ in GitHub AI credits to the Azure subscription linked to your Azure DevOps organization, so you can track costs and set\
  \ budget alerts in Azure Cost Management.\n\n To get started, see Get started with Copilot code review for pull requests\
  \ in the Azure DevOps documentation.\n\n\n\n The post Copilot code review: Adaptive effort, secret detection, and more appeared\
  \ first on The GitHub Blog ."
