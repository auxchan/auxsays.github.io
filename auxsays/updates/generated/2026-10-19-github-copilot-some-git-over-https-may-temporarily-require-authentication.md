release_summary: "During periods of unusual traffic, GitHub may temporarily require authentication for some clones and fetches\
  \ of public repositories over HTTPS to help protect github.com’s availability. If an operation is affected, it will fail\
  \ with a message indicating that authentication is required.\n\n\n To continue, authenticate and retry the operation. You\
  \ can also wait and retry without authentication after the temporary protection has been lifted.\n\n\n GitHub applies this\
  \ protection as narrowly as possible using signals associated with anomalous traffic. Because legitimate and anomalous traffic\
  \ can sometimes share those signals, legitimate unauthenticated operations may occasionally be affected. This is not a general\
  \ authentication requirement for public repositories.\n\n\n The following operations are unaffected:\n\n\n\n Authenticated\
  \ Git operations over HTTPS\n Git operations over SSH\n Pushes\n Unrelated GitHub web and API traffic\n\n For more reliable\
  \ automated clones and fetches, configure authentication:\n\n\n\n GitHub Actions: Use the built-in GITHUB_TOKEN .\n Other\
  \ CI systems: Prefer a GitHub App installation access token. A personal access token can also be used.\n Operations that\
  \ cannot authenticate: Retry after the temporary protection has been lifted.\n\n This protection applies to repositories\
  \ on github.com across all plans.\n\n\n For setup instructions, see about authentication to GitHub and managing remote repositories\
  \ .\n\n\n\n The post Some Git over HTTPS may temporarily require authentication appeared first on The GitHub Blog ."
