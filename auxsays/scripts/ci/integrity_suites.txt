# AUXSAYS CI test-governance manifest.
#
# CLOSED WORLD: every test file under auxsays/scripts/tests/ must appear in exactly one category
# below. The runner fails if a test file exists that is classified nowhere (so a new test cannot
# silently bypass CI), if a category names a file that does not exist (so coverage cannot silently
# shrink), or if any file is listed twice. Listing is explicit rather than glob-discovered for
# exactly that reason.
#
#   blocking              run by CI, must pass. Deterministic, offline, proven not to write.
#   diagnostic            run by CI, must pass. Deterministic but broader/slower, or protecting
#                         presentation rather than patch correctness.
#   network               NOT run: makes live external requests. Transport availability is not PR
#                         correctness; it belongs to the scheduled source-health lanes.
#   mutating              NOT run: writes the live checkout. Would silently revert a contributor.
#   environment_specific  NOT run: needs tooling absent from the runner, and reports green anyway.
#   stale                 NOT run: currently failing for a test-side reason, with a named follow-up.
#
# Every entry outside `blocking`/`diagnostic` carries the reason it is excluded. Nothing is excluded
# without one.
#
# Entries are REPO-RELATIVE PATHS, and discovery is repo-wide and recursive: a single non-recursive
# glob of one directory let a new suite bypass CI five ways (a `*_test.py` suffix, a subdirectory,
# another tests root, the repo root, a file beside the runner), and three real .mjs suites were
# already living outside the closed world.
#
# Executed entries declare `= N`, the governed number of checks the suite must report. A
# self-consistent summary proves nothing about how much work was done -- `0/0 passed, 0 failed` is
# perfectly consistent and perfectly empty -- so this number is what makes silent coverage loss a
# failed build. Change it deliberately, in the same commit as the test change.
